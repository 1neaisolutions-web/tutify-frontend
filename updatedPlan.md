Tutify AI Product Improvement Plan
AI Coach Desk Enhancement and Teaching Action Studio Proposal
1. Purpose
Tutify already has several useful AI capabilities for teachers, but the current product structure does not present them clearly enough.
The main issue is not a lack of features. The issue is that different types of AI tools are currently mixed together without a clear role.
At present, the product includes:
A real conversational teaching assistant
Subject-specific guided tools
Classroom document templates
Quiz and image-generation tools
Some partially completed chatbot pages
Some mock or static pages presented like working AI products
Because these experiences are grouped under “Specialized Chatbots,” the section feels inconsistent. A teacher can open one tool and receive a real conversation, open another and see a structured form, and open another where some tabs or buttons are not fully functional.
My recommendation is not to remove the existing chatbot section. We should improve it, rename it, reduce weak or misleading features, and give every AI product area a clear purpose.
At the same time, we should introduce one new premium product area for deeper teacher workflows: Teaching Action Studio.

2. Current Chatbot Problems
2.1 The current name creates the wrong expectation
The title “Specialized Chatbots” suggests that every tool will work like a chatbot.
In reality, the current system contains two different types of experiences:
General Teaching Assistant
This is a real conversational tool. The teacher writes a message, receives a streaming response and can continue the conversation.
Specialist tools
Most specialist tools are not chatbots. They work through guided inputs.
For example:
The teacher selects a capability.
The teacher enters grade, subject, topic or instructional context.
The system processes the request.
A structured result is displayed in cards.
This is useful, but it is not a normal chatbot experience. Calling every tool a chatbot creates confusion.

2.2 Too many tools are presented at the same level
The current section shows a large number of individual bots.
This creates choice overload and makes it difficult for teachers to understand:
Which tool they should use
Which tools are complete
Which tools are general
Which tools are subject-specific
Which tools generate documents
Which tools only provide quick guidance
A smaller, curated structure would feel more professional than a large catalog of separate bots.

2.3 Some experiences are incomplete or mock-based
Some existing chatbot pages contain:
Mock responses
Hardcoded outputs
Buttons without working actions
Tabs without backend connections
Download options that do not create real files
Static content presented as AI functionality
These features may look impressive during initial viewing, but they reduce confidence when a user tries to use them.
The product should show fewer working features rather than many incomplete features.

2.4 Model-branded pages create unnecessary risk
The current product includes pages branded around GPT, Claude and Gemini-style experiences, but these pages are not connected to complete production integrations.
These pages should not remain visible.
Tutify should build its own trusted education AI identity rather than presenting model names that are not fully integrated into the product.
The stronger product message is:
Tutify provides specialized education intelligence designed for teachers.

2.5 The current UI is too tab-heavy
Many specialist pages display several horizontal tabs.
Some tabs perform real actions, while others contain static examples or incomplete functionality.
This makes the pages feel unfinished.
The rule should be simple:
A capability should only appear in the interface when it has a real backend connection and produces a useful result.

2.6 Chatbots overlap with Templates
Some chatbot capabilities create outputs that are already available through the Templates Library.
Examples may include:
Lesson documents
Rubrics
Worksheets
Parent communication
Vocabulary lists
Assessment material
Classroom plans
This overlap makes it difficult to understand why a teacher should use one area instead of another.
We need a clear product boundary between AI coaching, document generation and complete teacher workflows.

3. Proposed Solution: Improve, Do Not Remove
The current chatbot section should remain in Tutify, but it should be renamed and repositioned.
Recommended new name
AI Coach Desk
The existing /chatbots route can remain for technical compatibility, but the visible name should change from “Specialized Chatbots” to “AI Coach Desk.”
Why this name is better
“AI Coach Desk” communicates that the section provides:
Quick instructional support
Subject guidance
Analysis
Rewriting
Idea generation
Guided mini-tools
Practical classroom recommendations
The word “Coach” feels more professional and human than “Bot.”
The word “Desk” suggests one central place where a teacher can find different types of support.

4. AI Coach Desk Product Role
The AI Coach Desk should focus only on short and focused teacher needs.
Examples include:
Analyze the complexity of this reading passage.
Suggest ways to explain this concept.
Improve these student instructions.
Create differentiated practice ideas.
Review this writing sample.
Suggest an inquiry activity.
Explain a coding concept.
Recommend ways to suort student engagement.
The Coach Desk should not become a full document factory.
It should also not become the place for large intervention, assessment or school-action workflows.
Its purpose is:
Help teachers think, analyze, improve and act quickly.

5. Recommended AI Coach Desk UI Flow
5.1 Main AI Coach Desk page
When a teacher opens AI Coach Desk, the page should not look like a large marketplace of unrelated bots.
The page should have a clean professional structure.
Page header

Quick instructional support for classroom questions, analysis, rewriting and subject-specific coaching.
The header should be compact. We should avoid a large marketing-style hero section.

The General Teaching Coach should remain a real conversation experience.

Right side: Actions

5.6 Search and filters
Search and filters can be added after the category structure is stable.

Useful future filters may include:

Coach type

5.7 Future personalization
Personalization should be added later as a separate improvement.
At present, Coach Desk can use teacher-entered context such as grade, subject and topic.
In the future, Tutify Personalization can help by:
Recommending the most relevant coaches
Prefilling the teacher’s grade
Prefilling subject areas
Remembering curriculum preferences
Remembering preferred output style
Showing recently used capabilities
Recommending tools based on previous activity
This should be introduced after the basic Coach Desk experience is stable.

7. Why We Need Another Product Area
Improving the Coach Desk will solve quick teacher-support needs, but there is still an important gap.
Tutify currently supports:
Quick teacher support
Through the General Teaching Coach and subject-specific capabilities.
Individual document generation
Through Templates.
What is still missing is a structured system that helps a teacher complete a more complex professional task from beginning to end.
This is where Teaching Action Studio is needed.

8. Proposed New Product Area: Teaching Action Studio
What Teaching Action Studio means
Teaching Action Studio is a home for advanced teacher workflow tools.
It is not one single tool.
It is a product area that can contain several focused modules over time.
Example structure:
Intervention Sprint Studio
Behavior Support Planner
Attendance Recovery Planner
Assessment Action Planner
Family Communication Planner
We should not build all of these immediately.
The first objective is to build one strong flagship module and use it as the quality standard for future modules.

9. How Teaching Action Studio Works
The teacher starts with a real classroom situation rather than a simple prompt.
For example:
Six Grade 5 students are struggling with fractions. Their recent exit tickets show that they do not understand equivalent fractions. I have 15 minutes per day to support them.
The teacher opens the relevant Action Studio module.
The workflow then guides the teacher through a small number of focused steps.
Step 1: Select the task
Example:
Create a Student Intervention Sprint
Step 2: Enter classroom context
The teacher provides:
Grade
Subject
Skill or topic
Student group
Evidence
Available time
Support needs
Expected goal
Step 3: Generate the working plan
The system creates one connected plan.
It is important to understand that the system is not creating seven unrelated documents.
It creates one plan with several connected sections.
Step 4: Review and adjust
The teacher can:
Make the plan easier
Make it more rigorous
Add English learner support
Change the daily time
Change the group type
Regenerate one section
Save the plan
Export the final result
Step 5: Use and monitor
The teacher can return to the plan through History, review progress and update the intervention if required.

10. First Recommended Module
Intervention Sprint Studio
Simple purpose
Intervention Sprint Studio helps a teacher convert classroom evidence into a short, practical student-support plan.
Example situation
A teacher knows that a group of students is struggling, but the teacher does not have enough time to:
Analyze the problem
Plan daily support
Create differentiated activities
Decide how to measure improvement
Prepare family communication
Prepare notes for an instructional coach or MTSS meeting
Intervention Sprint Studio completes this work in one guided flow.

What the teacher enters
Grade level
Subject
Topic or skill
Student group type
Main concern
Assessment or observation evidence
Time available each day
Support requirements
Intervention duration
The teacher should use anonymous labels such as “Group 1” or “Student A” rather than entering real student names.

What the teacher receives
The system creates one complete intervention plan containing:
1. Problem summary
What the evidence suggests students are struggling with.
2. Intervention goal
What improvement should be achieved during the selected period.
3. Daily action plan
What the teacher should do each day.
4. Differentiation
How the activity should be adjusted for different student needs.
5. Progress monitoring
How the teacher will check whether the intervention is working.
6. Teacher guidance
Suggested explanations, questions or feedback language.
7. Family communication
A clear and respectful update that the teacher can adapt.
8. Admin or MTSS summary
A short professional record of the concern, action taken and review method.
Again, this is one connected plan—not multiple separate products.

11. Business Reason for Adding Teaching Action Studio
11.1 It fills the gap between advice and execution
AI Coach Desk gives teachers quick guidance.
Templates give teachers individual documents.
Neither one fully helps the teacher manage a real classroom problem from initial evidence through action and monitoring.
Teaching Action Studio fills that gap.

11.2 It creates a stronger premium reason to use Tutify
Quick AI advice is becoming common.
Basic lesson plans and document generation are also becoming common.
A guided workflow that helps a teacher complete a real professional responsibility is more valuable and more difficult to replace with a generic chatbot.
This can strengthen Tutify’s premium positioning.

11.3 It expands the target user
The Coach Desk and Templates mainly support individual teachers.
Teaching Action Studio can also be useful for:
Instructional coaches
Interventionists
MTSS coordinators
Assistant principals
School leaders
Curriculum teams
This gives the product a stronger school and district value proposition.

11.4 It creates future expansion opportunities
Once the first Action Studio workflow is proven, the same structure can support other school problems.
Possible future modules include:
Behavior Support Planner
Attendance Recovery Planner
Assessment Action Planner
Family Communication Planner
Lesson Improvement Planner
Each module can use the same basic framework:
Guided classroom inputs
Structured plan generation
Review and refinement
Save and history
Export and reuse

11.5 It reduces random feature development
Without a clear product structure, every new idea may become another chatbot or another template.
Teaching Action Studio gives the team a clear home for advanced workflow products.
This reduces duplication and improves product consistency.

14. Recommended Implementation Order
Phase 1: Improve current chatbot experience
Rename Specialized Chatbots to AI Coach Desk
Remove fake or incomplete tools from discovery
Remove fake ratings and fake exports
Hide non-working capabilities
Show only real production tools
Reorganize tools into clear coach categories
Improve General Teaching Coach

Phase 2: Improve Coach Desk UI
Build category cards
Build capability cards
Open capabilities in full-page workspaces
Use guided inputs
Use structured results
Add real copy, save and history actions
Add related Template links
Phase 3: Build Teaching Action Studio foundation
Create Teaching Action Studio home
Create the first flagship card
Build Intervention Sprint Studio
Reuse existing streaming, history and export strengths where possible
Test with real teacher scenarios
Phase 4: Evaluate before expansion
Before creating more Action Studio modules, review:
Teacher usage
Output quality
Time saved
Repeat usage
Export usage
School/admin interest
Most common refinement actions
Only then should we decide which Action Studio module to build next.

15. Final Recommendation
We should not remove the current chatbot section.
We should improve it and give it a clearer role.
The immediate product decision should be:
Rename Specialized Chatbots to AI Coach Desk.
Keep only real and useful coaching capabilities.
Remove or hide mock, static and incomplete experiences.
Replace the large bot catalog with clear coach categories.
Use a proper chat experience for General Teaching Coach.
Use guided full-page capability workspaces for specialist coaches.
Keep Classroom Templates focused on individual documents.
Introduce Teaching Action Studio for advanced teacher workflows.
Launch Intervention Sprint Studio as the first Action Studio module.
Build fewer features, but make each visible feature complete and trustworthy.
The intended product structure is:
AI Coach Desk for quick support.
Classroom Templates for individual documents.
Teaching Action Studio for complete teacher tasks.
This structure makes Tutify easier to understand, improves product trust and gives us a stronger path for future growth.
